## Overview

This project analyzes a retail customer shopping dataset to understand **revenue, purchasing behavior, product performance, discounts, subscription status, shipping preferences, and customer purchase history**.

The project follows a practical analytics workflow:

**Business Problem → Data Cleaning → Feature Preparation → KPI Analysis → SQL Analysis → Power BI Reporting**

The analysis was performed on **3,900 purchase records** containing customer, product, transaction, promotion, subscription, and shipping information.

---

## Business Problem

The objective is to answer practical business questions from customer purchase data, including:

- Which customer groups generate the most revenue?
- Which products and categories perform strongly?
- How do subscribers and non-subscribers differ?
- What is the relationship between discounts and purchase amount?
- Do shipping preferences correspond to different average purchase values?
- How are customers distributed by previous purchase history?
- Which products are most frequently purchased within each category?
- How does revenue vary across age groups?

The output is a combination of **cleaned data, reproducible analysis, SQL queries, and an interactive Power BI report**.

# 1. Data Preparation

The notebook performs the main data preparation required before analysis.

### Missing-value handling

The dataset contains **37 missing Review Rating values**.

Missing ratings are filled using the **median review rating within the corresponding product category** rather than applying one global value to every missing observation.

### Column standardization

Column names are converted to a consistent format:

~~~text
Purchase Amount (USD)
        ↓
purchase_amount
~~~

### Age groups

Customer ages are converted into four quartile-based groups:

- Young Adult
- Adult
- Middle-aged
- Senior

### Purchase frequency

Categorical purchase-frequency values are converted into approximate day intervals for analysis.

### Redundant field check

**Discount Applied** and **Promo Code Used** are compared during preparation. The analysis treats **Promo Code Used** as redundant for this dataset and removes it from the cleaned DataFrame.

# 3. SQL Analysis

The cleaned data is loaded into a relational database and analyzed using SQL.

The repository contains **10 business questions**.

| # | Business Question | Main SQL Concepts |
|---:|---|---|
| 1 | Revenue generated by male vs. female customers | GROUP BY, SUM |
| 2 | Customers using discounts while spending above average | Subquery, AVG |
| 3 | Top 5 products by average review rating | AVG, GROUP BY, ORDER BY |
| 4 | Average purchase amount for Standard vs. Express shipping | AVG, filtering |
| 5 | Subscriber vs. non-subscriber purchase behavior | COUNT, AVG, SUM |
| 6 | Products with the highest percentage of discounted purchases | CASE, aggregation |
| 7 | New / Returning / Loyal customer segmentation | CASE, CTE |
| 8 | Top 3 products within each category | CTE, ROW_NUMBER |
| 9 | Repeat buyers by subscription status | Filtering, GROUP BY |
| 10 | Revenue contribution by age group | GROUP BY, SUM |

### SQL techniques used

- Aggregations
- Filtering
- Subqueries
- CASE expressions
- Common Table Expressions
- Conditional aggregation
- Window functions
- Ranking
- Grouped comparisons

The SQL file is written for **PostgreSQL**.

---

# 4. Customer Segmentation

Customer purchase history is used to create three descriptive segments:

~~~text
Previous Purchases = 1
        ↓
      New

Previous Purchases = 2–10
        ↓
   Returning

Previous Purchases > 10
        ↓
      Loyal
~~~

The segmentation is then used to examine the distribution of customers across purchase-history groups.

---

# 5. Product Analysis

The project examines product performance from multiple perspectives.

### Revenue

Identifies products contributing the most revenue.

### Ratings

Ranks products using average review rating.

### Purchase volume

Uses transaction counts to identify the most frequently purchased products within each category.

### Discounts

Calculates the percentage of purchases receiving discounts for individual products.

This gives both a **revenue view** and a **customer activity view** of product performance.

---

# 6. Subscription Analysis

Subscriber and non-subscriber groups are compared using:

- Number of customers
- Average purchase amount
- Total revenue

The analysis is descriptive: it compares observed behavior between the two groups without claiming that subscription status causes differences in spending.

~~~bash

~~~

Open:

**Customer_Shopping_Behavior_Analysis.ipynb**

Run the notebook **from top to bottom** because later cells depend on the cleaned **df** DataFrame created earlier in the workflow.
